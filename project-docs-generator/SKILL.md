# 项目文档生成器（Project Docs Generator）

**重要：本 skill 只能由用户手动调用。** 不得因编写代码、审阅代码等场景自动触发。仅当用户明确表达"生成项目文档 / 更新 CLAUDE.md / 为模块生成 skill"等意图时，才执行以下流程。

## 作用

为当前项目生成/更新项目说明文档与项目级 skill，供 AI-Agent（如 TraeCode）在后续开发中**自动调用**以快速了解项目结构、技术栈、各模块与各文件的功能。

## 输出产物

### 1. 根目录 `CLAUDE.md`
在**当前项目根目录**生成（已存在则更新，不重复累加）：
- 项目名称与一句话概述
- 技术栈（框架、语言、构建工具、主要依赖）
- 顶层目录结构说明
- 常用命令（安装/开发/构建/测试）
- 项目级编码约定与注意事项（如有）

### 2. 项目级 skill（每个子模块一个）
为每个子模块生成/更新一个独立 skill，存放于该模块项目内的：

```
<项目根目录>/.trae/skills/<module-name>/SKILL.md
```

模块 skill 内容要求**精确到每个功能、每个文件的作用**：
- 模块概述与职责边界
- 目录结构树（从该模块入口逐层展开）
- **逐文件说明**：每个文件的功能、导出的关键对象/方法、依赖关系
- **逐功能说明**：模块提供的主要功能点与其实现位置
- 与其他模块的交互关系
- 关键数据流 / 调用链（如有）

> 将模块 skill 放在项目 `.trae/skills/` 下，AI-Agent 才可在后续开发中被自动匹配调用，从而在相关文件上获取模块上下文。

## 执行步骤

1. 确认当前工作目录即目标项目**根目录**。若不是，先定位到根目录。
2. 扫描项目结构：
   - 读取根目录文件（`package.json`、`vite.config.*`、`tsconfig*.json`、`README.md`、已有 `CLAUDE.md` 等）确定技术栈与运行命令。
   - 用 `LS` / `Glob` / `Grep` 浏览目录，识别各子模块及其核心文件。
3. 生成/更新根目录 `CLAUDE.md`（见上）。
4. **确定子模块范围**：
   - 若用户指定了某几个子模块，仅处理这些模块。
   - 若未指定，遍历项目下各子模块目录逐个处理。
5. 对每个子模块：
   - 深入阅读其目录结构与关键源码，提炼逐文件、逐功能说明。
   - 创建/更新 `<项目根目录>/.trae/skills/<module-name>/SKILL.md`。
6. 处理完成后，向用户汇报：已生成/更新的文件清单与各模块 skill 的存放路径。

## 注意事项

- **只读分析 + 写入文档**：本 skill 的分析与阅读不影响代码；仅向目标文档文件写入内容。
- **不生成多余文件**：除根目录 `CLAUDE.md` 与各模块 `SKILL.md` 外，不创建其他文件。
- **增量更新**：文档已存在时在此基础上更新，避免破坏已有有效内容。
- 生成后应向用户确认文档质量，必要时按反馈迭代。核心交付物是这两个文件，请真实阅读代码后填写，不要编造功能与文件作用。
